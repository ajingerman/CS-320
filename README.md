# CS-320
Repository created for CS 320 portfolio

How can I ensure that my code, program, or software is functional and secure?

I can make sure my software is functional by testing it against the requirements and checking both expected and unexpected inputs. In this course, I used JUnit tests to check valid values, invalid values, null values, duplicate IDs, and boundary conditions. Testing exact limits and then one value beyond them helped me make sure the code accepted what it should and rejected what it should not. I also learned that high code coverage is useful, but it does not mean every possible problem has been tested. To make software more secure and reliable, I need to keep looking for cases that may have been missed instead of assuming that passing tests mean the code is finished.

How do I interpret user needs and incorporate them into a program?

I start by breaking user needs into specific requirements that can be turned into code and tested. For the Contact, Task, and Appointment services, the requirements explained things such as which fields were required, how long values could be, and which operations the services needed to support. I used those details to decide what validation belonged in the classes and what behaviors needed JUnit tests. This helped me see that user needs are easier to work with when they are turned into clear rules that can be checked during development.

How do I approach designing software?

I approach software design by working in small parts and testing as I go instead of trying to build everything at once. I like to get one class or feature working, test it, and then move on to the next part. This makes it easier for me to find where a problem started if something stops working. I also try to keep the code and tests simple enough that their purpose is clear. As I continue learning, I want to keep improving this process by thinking more about edge cases, how different parts of a program interact, and what could happen when the software is used in ways I did not originally expect.
